# Do Not Build — 9Th-Grade AI

Ideas that sound futuristic but would make the product worse, and why.

1. **AI chat on every tab.** Tutor-in-a-drawer everywhere trains users to ask instead of do;
   support cost explodes, acceptance unmeasurable. Keep AI at decision moments (result, mistake,
   brief), not as furniture.
2. **Generative metrics.** Any number rendered from tokens (readiness %, predicted score) destroys
   trust at the first wrong digit. Numbers stay deterministic; LLM narrates only.
3. **Decorative AI animations** (typing dots for deterministic content, orb loaders, sparkle bursts).
   Motion must communicate state; the product is unused exam prep, not a demo.
4. **More dashboards/cards.** The current 11-tab sprawl is already the problem. Consolidate before
   adding; every new surface must retire or merge an old one.
5. **Streak/gamification expansion** (gems, leagues, frenemies). Competitive-exam prep is anxious
   enough; streaks punish sick days. Keep the quiet streak; never build punishment loops.
6. **Push/email notification blasts.** Revision reminders opt-in only, digest max 1/day. Noise gets
   the app muted and kills the highest-value channel.
7. **Giant command center / "mission control" Home.** Density without decision is clutter. One brief,
   one mission, one strip — then get out of the way.
8. **Over-personalization on thin data.** First-week users get archetype playlists, not a "model of
   you" — cold-start confidence theater erodes trust.
9. **Expensive models for trivial tasks.** Narration/briefs run fast-tier; primary-tier reserved for
   planning/generation. The $0.50/day budget is a feature, not a constraint to outgrow silently.
10. **Social/leaderboard expansion** (friends, challenges, public profiles). IDOR-grade privacy
    surface + moderation burden for near-zero learning impact. Leaderboard stays anonymous-opt-in.
11. **PDF/export proliferation.** Real-exam print export exists and suffices; every new export format
    is maintenance without learning gain.
12. **A rewrite (frontend framework, state lib, DB).** The seam (thin routes/services/repos),
    idempotent exam core, and token system are assets. Refactor by extraction (`useExamSession`),
    never by rewrite.
